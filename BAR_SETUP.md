# Линия спорта — спортбар: подготовка подключения

**Домен:** https://bar.liniyasporta.ru/ (базовый домен сети — только `liniyasporta.ru`).

**Хостинг:** REG.RU, услуга `u3652448`, сервер `server169.hosting.reg.ru:21`.

**FTP-пользователь:** `u3652448_bar`.

**Протокол:** explicit FTPS (FTP + STARTTLS), пассивный режим, порт 21.

**Путь в панели REG.RU:** при настройке FTP-пользователя назначить исключительно каталог, соответствующий сайту `/www/bar.liniyasporta.ru`, предварительно проверив его фактический путь в панели. Для FTPS-клиента корень этого пользователя — `/`.

**GitHub Actions secret:** `BAR_REG_PASSWORD` в репозитории `lsevmos-gpt/ls-promo`.

## Порядок подключения

1. Убедиться, что поддомен `bar.liniyasporta.ru` создан и привязан к нужному каталогу на действующем хостинге `u3652448`; настроить DNS и HTTPS.
2. В REG.RU проверить, что пользователь `u3652448_bar` активен, ему назначен отдельный каталог спортбара, и установить отдельный надёжный пароль FTP.
3. В GitHub → Settings → Secrets and variables → Actions добавить репозиторный секрет `BAR_REG_PASSWORD` с **тем же** паролем. Пароль в чат не отправлять.
4. Запустить `Bar | REG.RU FTPS — read-only connection check` вручную. Его можно также инициировать изменением `.github/trigger-bar-ftps-check.txt`. Проверка не меняет файлы.
5. После подготовки реального меню разместить готовый сайт в `bar-site/`, включая `index.html`.
6. Выполнить `Bar | REG.RU FTPS — guarded manual deployment` в режиме `plan`. Для публикации вручную выбрать `deploy` и ввести точное подтверждение `bar.liniyasporta.ru`.

**Публикация никогда не запускается автоматически при изменении файлов сайта.** Она требует ручного запуска и доказательства привязки FTP-каталога к домену. При первой публикации без доменного маркера исходный удалённый `index.html` должен побайтно совпадать с текущим HTTPS-сайтом.

Сайт спортбара и меню пока не опубликованы. На всех клубах планируется единое меню без выбора клуба. Алкоголь в ассортимент не включается.

Файлы действующих сайтов (`new`, `promo`, `docs`, `massage`) и их workflows не менять.
