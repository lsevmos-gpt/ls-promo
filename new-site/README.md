# Новый основной сайт «Линия спорта»

Этот каталог предназначен **только** для нового сайта. Действующий `promo-site/` не изменяется.

## Публикация

Workflow: `.github/workflows/deploy-new-site.yml`.

Первый этап: запустить **Actions → New Linea Sporta site — REG.RU FTPS → Run workflow → mode: check**. Он только проверяет FTPS и просматривает удалённую директорию без записи.

Для теста нужно создать в репозитории **Settings → Secrets and variables → Actions**:

Repository variables:
- `NEW_SITE_DOMAIN` — точный адрес поддомена (в запросе указан `new.linea-sporta.ru`; сверить с панелью REG.RU, поскольку действующий сайт сети использует `liniyasporta.ru`).
- `NEW_SITE_FTP_HOST` — FTP-сервер (например, `server169.hosting.reg.ru`, только если его подтверждает панель хостинга).
- `NEW_SITE_FTP_USER` — логин выделенного FTP-пользователя нового сайта.
- `NEW_SITE_FTP_DIR` — удалённый каталог этого пользователя (обычно `/` при изоляции в каталоге сайта; проверить в REG.RU).

Repository secret:
- `NEW_SITE_FTP_PASSWORD` — пароль выделенного FTP-пользователя. **Не добавлять пароль в репозиторий, README или переписку.**

Перед первой публикацией проверить, что FTP-пользователь ограничен корнем правильного сайта, и создать в его каталоге файл `.new-site-root.txt` с единственной строкой — точным значением `NEW_SITE_DOMAIN`. Это предотвращает случайную отправку файлов в каталог другого сайта.

После этого разместить **готовые статические файлы сайта** в `new-site/` (в том числе `new-site/index.html`). Первый запуск публикации только вручную: **mode: deploy**, `confirm_domain` — точное значение `NEW_SITE_DOMAIN`.

Workflow сначала делает резервную копию подходящих публичных файлов, затем загружает содержимое `new-site/` через защищённый FTPS, **не удаляя чужие файлы на сервере**, и проверяет главную страницу по HTTPS. Если сайт требует серверной сборки, перед публикацией добавить этап сборки и выбрать выходной каталог; текущий сценарий рассчитан на готовые статические файлы.

Автоматическую публикацию после каждого обновления `new-site/` включать **только после успешного теста**. До этого существующие сайты и хостинг нового сайта не изменяются этим workflow.
