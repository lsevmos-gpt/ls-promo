Настроен отдельный контур публикации в существующем репозитории `lsevmos-gpt/ls-promo`. Содержимое действующего промосайта `promo-site/` и его workflow не изменяются.

## Настройки уже зафиксированы в GitHub Actions

- Публичный адрес: `https://new.liniyasporta.ru/`
- FTP-пользователь: `u3652448_new`
- Каталог на хостинге: `/www/new.liniyasporta.ru`
- FTP-сервер по умолчанию: `server169.hosting.reg.ru` (унаследован из действующих сайтов на REG.RU; при другом сервере задать GitHub variable `NEW_SITE_FTP_HOST`).
- FTPS: порт 21, обязательное TLS-соединение и проверка сертификата.
- Каталог FTP в сценарии: `/www/new.liniyasporta.ru`. Если FTP-пользователь ограничен своим каталогом (chroot) и видит его как `/`, переопределить каталог через GitHub variable `NEW_SITE_FTP_DIR` = `/` **после диагностики**.
- Файлы сайта в GitHub: `new-site/`.
- Workflow: `.github/workflows/deploy-new-site.yml`.
- Сейчас публикация только вручную, без запуска при каждом `push`.

## Что нужно сделать один раз

1. Открыть `https://github.com/lsevmos-gpt/ls-promo/settings/secrets/actions`.
2. **Repository secrets → New repository secret**: Name = `NEW_SITE_FTP_PASSWORD`, Value = действующий пароль пользователя `u3652448_new`. Не передавать пароль в переписку и не сохранять его в репозитории.
3. **Actions → New Linea Sporta site — REG.RU FTPS → Run workflow**: выбрать `mode: check`, поле `confirm_domain` оставить пустым. Этот запуск **не меняет содержимое FTP**: лишь проверяет вход и каталог.
4. Если команда `cd /www/new.liniyasporta.ru` не работает, но соединение проходит, проверить, не видит ли FTP-пользователь свой каталог как `/`. В таком случае добавить **Repository variable** `NEW_SITE_FTP_DIR` = `/` и повторить `check`. Проверить права пользователя и соответствие каталога поддомену прежде чем публиковать.

## Перед первой публикацией

- В файловом менеджере хостинга (или по FTP) создать **на удалённой стороне** файл `/www/new.liniyasporta.ru/.new-site-root.txt` с единственной строкой:

```text
new.liniyasporta.ru
```

  Если для FTP-пользователя каталог сайта представлен как `/`, создать файл в нём. При несовпадении маркера workflow откажется публиковать.

- Разместить готовые статические файлы нового сайта в `new-site/` репозитория, в том числе `new-site/index.html`.
- **Actions → New Linea Sporta site — REG.RU FTPS → Run workflow**: `mode: deploy`, `confirm_domain: new.liniyasporta.ru`.

При публикации workflow проверит правильный каталог по маркеру, сделает резервную копию подходящих существующих публичных файлов в артефакт запуска (на 7 дней), отправит статические файлы через FTPS **без удаления чужих файлов** и сравнит опубликованную главную страницу с `new-site/index.html` по HTTPS. Конфиденциальные серверные файлы не включены в резервную копию.

Если сайт собирается Node/Vite/другим сборщиком, требуется добавить этап сборки и выбрать выходную папку вместо `new-site/`. Автопубликацию из GitHub при `push` включать только после первой подтверждённой успешной публикации.
